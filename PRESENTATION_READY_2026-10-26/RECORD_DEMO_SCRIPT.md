# บทอัดคลิปเดโม — กดอ่านภาพจริงจนถึง Home Assistant

**แผนที่เลือก:** ณัชพลอัดการใช้งานจริงบน PC ล่วงหน้า เริ่มจากกด **อ่านภาพด้วยระบบ** ตรวจแก้ด้วยตนเอง แล้วส่งเข้า Home Assistant คลิปฉบับใช้พรีไม่เกิน **2:00 นาที** เปิดในสไลด์ 18 เวลาพรีรวมเป้า 9 นาที เผื่อ 1 นาที

เอกสารนี้เป็นบทสำหรับอัด ยังไม่ได้ยืนยันว่ามีคลิปหรือมีข้อมูลที่เจ้าของงานตรวจแล้ว เปิด [คู่มือทีละคลิก](CLICK_BY_CLICK_GUIDE.html) หากต้องการรายละเอียดแต่ละช่อง

## 1. เตรียมก่อนกดบันทึก

1. เปิด `Seminar\DEMO_PRESENTATION_2026-10-21\OPEN_DEMO.cmd` ให้สำเร็จ แล้วเปิดแท็บ A `http://127.0.0.1:8090/demo` และแท็บ B `http://127.0.0.1:8123/config/tools/state`
2. ล็อกอิน Home Assistant ให้เสร็จ **ก่อนอัด** ปิดหน้าต่างแชต/ไฟล์รหัสผ่าน/การแจ้งเตือนที่ไม่ต้องการบันทึก
3. ที่แท็บ B เลือก **States** กรอก `sensor.seminar_` ในช่อง **Filter entities** ใต้คอลัมน์ Entity เปิด **Attributes** ไว้ ค่าเดิมอาจเป็นของ Robot ให้ตรวจใหม่หลังยืนยันรอบอัดจริง
4. กลับแท็บ A เข้า URL `/demo` ที่ไม่มี `?receipt=...` เพื่อเริ่มจากหน้าที่ยังไม่ได้เลือกผลย้อนหลัง **ไม่เลือกจากเมนูรายการที่บันทึกไว้เพื่อทำเป็นการอ่านครั้งใหม่**
5. เลือกภาพ **R74946CAAC57E** ในเมนูซ้ายสุด และ **หมุนทวนเข็ม 90°** ในเมนูถัดไป ตรวจภาพให้แน่ใจว่าต้องใช้ทิศนี้
6. เตรียมอ่านใบซื้อสินค้าจริงล่วงหน้าได้ แต่ตอนอัดต้องกดอ่านภาพใหม่และตรวจผลรอบใหม่ทุกช่อง อย่านำชื่อสินค้า/วันที่จากฟอร์ม Robot มาใช้เป็นเฉลย
7. เปิดโปรแกรมบันทึกหน้าจอที่คุณใช้งานได้ เลือกให้เห็นทั้งหน้าเบราว์เซอร์ ตัวอักษรอ่านออก หากอัดเสียงพร้อมกันให้ลองสั้น ๆ และเปิดฟัง ตรวจว่าการสลับแท็บติดในภาพ
8. อัดเป็นไฟล์ต้นฉบับยาวได้ **ไม่ต้องทำทุกขั้นให้ทัน 2 นาทีขณะอัด** เก็บไฟล์ต้นฉบับไว้ แล้วตัดช่วงรอ/ย่อช่วงตรวจอย่างเปิดเผยในฉบับใช้พรี

## 2. ลำดับที่ต้องกดระหว่างอัดจริง

| ขั้น | คลิก/ทำอะไร | สิ่งที่ต้องบันทึกให้เห็น |
|---|---|---|
| 1 | เริ่มบันทึก กลับไปเลือกภาพและทิศอีกครั้งถ้าต้องการให้เห็นการเลือก | รหัส R74946CAAC57E และเมนูหมุนทวนเข็ม 90° |
| 2 | กด **อ่านภาพด้วยระบบ** หนึ่งครั้ง | เห็นการคลิกจริง ปุ่มจางลง และข้อความกำลังตรวจภาพ/อ่านรายการ |
| 3 | รอจนเสร็จ ไม่รีเฟรช ไม่กดอ่านซ้ำ | ภาพโหลดครบ กรอบสีเขียว ฟอร์มรอบใหม่ และปุ่มกลับมากดได้ |
| 4 | เลื่อนลง กาง **ผลจากเครื่องมือก่อนผู้ใช้แก้ไข** | ข้อความ OCR, JSON และรหัสรอบรัน ใช้รอบเดียวกับที่เพิ่งประมวลผล |
| 5 | กลับฟอร์ม เทียบภาพจริง ตรวจร้าน วันที่ ยอด สกุลเงิน และสินค้า | ชี้ข้อผิดพลาดที่เกิดจริง แก้ช่องที่ผิด ลบแถวที่ไม่ใช่สินค้า เพิ่มเฉพาะที่เห็นชัด |
| 6 | กรอก **ชื่อผู้ตรวจ** เป็นชื่อของคนที่ตรวจจริง แล้วกด **ยืนยันและส่งข้อมูล** | ชื่อผู้ตรวจ การคลิกยืนยัน ข้อความบันทึกการยืนยัน และ event ID |
| 7 | กด **ตรวจสถานะปลายทาง** รอค่า ถ้าจำเป็นกดตรวจอีกครั้ง | ข้อความ **ได้รับรายการที่เลือกแล้ว** และ event ของ sensor สองตัวตรงกัน |
| 8 | สลับแท็บ B ดู States ที่กรองไว้ | ยอดรวม จำนวนแถวสินค้า และ event_id ตรงกับรอบอัด ไม่ใช่ค่าค้างของ Robot |
| 9 | จบการบันทึก เก็บไฟล์ต้นฉบับและจด event ID | หลักฐานว่าภาพ ผลดิบ ฟอร์มที่ตรวจ และปลายทางเป็นรายการเดียวกัน |

หากอ่านภาพ/โมเดลล้มเหลวหรือผลว่าง อย่าตัดภาพผลเก่ามาต่อให้เหมือนรอบนี้สำเร็จ ให้แก้ปัญหาแล้วอัดรอบใหม่ หากอ่านข้อมูลสำคัญจากภาพไม่ได้ ให้หยุดยืนยันและบอกข้อจำกัด ไม่กรอกข้อมูลเดาเพื่อให้คลิปจบ

## 3. บทพากย์ฉบับตัดต่อ 120 วินาที

อ่านตามนี้ได้ แต่ให้ภาพตามขั้นตอนจริง เสียงพากย์อัดภายหลังได้เพื่อลดการพูดค้างระหว่างรอ **อย่าอ้างผลสำเร็จในเสียงถ้าภาพรอบนั้นยังไม่ยืนยัน**

| เวลาในคลิป | ภาพที่ใช้ | บทพากย์ |
|---|---|---|
| 0:00–0:12 | เลือกภาพและทิศ | “ตัวอย่างนี้ใช้ภาพจากชุดพัฒนาบน PC ครับ ผมเลือกภาพใบซื้อสินค้าและหมุนทวนเข็ม 90 องศาให้ระบบอ่านในทิศที่เหมาะสม” |
| 0:12–0:22 | คลิกอ่านภาพด้วยระบบ เห็นปุ่มและข้อความกำลังทำงาน | “จากนั้นกดอ่านภาพด้วยระบบ ให้ YOLO หาตำแหน่งเอกสาร แล้วส่งต่อไปยัง OCR และโมเดลภาษาภายในเครื่องครับ” |
| 0:22–0:30 | ตัดจากช่วงรอไปผลรอบเดิม พร้อมข้อความกำกับ | “ช่วงนี้ตัดเวลารอประมวลผลออกครับ เมื่อเสร็จจะเห็นกรอบเอกสารและข้อมูลที่ระบบอ่านได้” |
| 0:30–0:48 | ชี้กรอบ กางผลดิบ เลื่อนดู OCR/JSON และรอบรัน | “ข้อความ OCR และ JSON ตรงนี้เป็นผลดิบจากโมเดลของรอบที่เพิ่งอ่าน ยังมีข้อผิดพลาดได้ และเก็บแยกไว้สำหรับตรวจย้อนหลังครับ” |
| 0:48–1:20 | แสดงการตรวจเทียบภาพและแก้จริงอย่างน้อยหนึ่งจุดที่ผิด หากมี ย่อส่วนตรวจที่เหลือโดยระบุ | “ผมตรวจชื่อร้าน วันที่ ยอดสุทธิ และสินค้าเทียบกับภาพก่อนครับ ข้อความที่ไม่ใช่สินค้าต้องลบออก และแก้ค่าที่อ่านผิด การตรวจส่วนนี้ย่อให้เห็นขั้นตอนสำคัญ แต่ก่อนส่งต้องตรวจครบทุกช่องครับ” |
| 1:20–1:35 | กรอกชื่อ กดยืนยัน เห็น event ID | “เมื่อตรวจครบแล้วจึงใส่ชื่อผู้ตรวจ และกดยืนยันและส่งข้อมูล ระบบจะบันทึกผลหลังตรวจและส่งผ่าน MQTT ครับ” |
| 1:35–1:55 | ตรวจสถานะปลายทาง แล้วสลับไป HA States | “ผมตรวจยอดรวม จำนวนแถวสินค้า และ event ID ของทั้งสอง sensor ให้ตรงกับรอบที่ยืนยัน จึงยืนยันได้ว่าข้อมูลรอบนี้ถึง Home Assistant ครับ” |
| 1:55–2:00 | ค้างที่ค่าปลายทาง | “นี่เป็นการสาธิตการเชื่อมระบบ ส่วนความถูกต้องของโมเดลต้องประเมินแยกครับ” |

หากไม่ได้ตัดช่วงรอหรือไม่ได้ย่อการตรวจ ให้ปรับประโยคและข้อความกำกับให้ตรงกับคลิปจริง ไม่ต้องสร้างข้อผิดพลาดขึ้นมาเพื่อแสดงการแก้ ถ้าช่องนั้นถูกแล้วให้แสดงการตรวจว่าตรงกับภาพ

## 4. ข้อความบนคลิปและวิธีตัดให้ไม่เกิน 2 นาที

- ตอนเริ่ม: **สาธิตบน PC • ภาพจากชุดพัฒนา • ผู้ใช้เลือกทิศภาพ**
- ตอนข้ามช่วงรอ: **ตัดช่วงรอประมวลผล** แสดงตรงจุดตัด ถ้าจะใส่เวลารอ ให้ใช้ค่าที่วัดจากไฟล์อัดของรอบนี้จริง ไม่ใช้ 10.758 วินาทีจากตารางทดลองเก่า
- ตอนย่นการตรวจ: **ย่อช่วงตรวจแก้โดยผู้ใช้ — ตรวจครบก่อนยืนยัน**
- ตอนแสดงผลดิบ: **OCR / JSON ก่อนผู้ใช้แก้ไข**
- ตอนจบ: **การส่งถึงปลายทาง ≠ คะแนนความถูกต้องของโมเดล**

เก็บให้เห็นคลิกอ่านภาพ จุดเริ่มรอ ผลรอบใหม่ การตรวจแก้ ชื่อผู้ตรวจ คลิกยืนยัน และการเทียบ event อย่างชัดเจน ตัดความเงียบและช่วงรอได้ แต่ไม่ตัดจนสลับไปรายการคนละรอบ หลีกเลี่ยงการเร่งทั้งคลิปจนอ่านฟอร์มไม่ทัน

**ก่อนส่งออก:** ลดความยาวส่วนเมาส์เคลื่อนหรือเลื่อนหน้าซ้ำก่อน ไม่ลดช่วงเทียบ event จนตรวจไม่ได้ ส่งออกชื่อ `DEMO_2_MIN.mp4` วางใน `PRESENTATION_READY_2026-10-26` เก็บไฟล์อัดต้นฉบับแยกไว้ในเครื่อง

## 5. บทพูดก่อนและหลังเปิดคลิปบนเวที

**สไลด์ 18 — ก่อนเปิดคลิป ประมาณ 15 วินาที:**

> ตารางนี้เป็นค่าดิบจากการทดสอบการส่งเดิมครับ ต่อไปเป็นคลิปที่กดอ่านภาพจริง ตรวจแก้ และส่งเข้า Home Assistant โดยตัดช่วงรอประมวลผลและย่อช่วงตรวจเพื่อให้เห็นขั้นตอนภายในสองนาทีครับ

ใช้ประโยคนี้เมื่ออัดและตัดต่อเสร็จตามแผนแล้ว ถ้าการตัดต่อจริงต่างออกไป ให้ปรับคำเปิดตามจริง เปิดคลิปโดย Alt + Tab ไปเครื่องเล่นที่เตรียมไว้ ไม่พูดทับเสียงพากย์

**หลังคลิปจบ:** Alt + Tab กลับ PowerPoint Slide Show กดไปหน้า 19 และพูดบทหน้า 19 จาก [SCRIPT_10_MIN_REVIEWED_v3.md](SCRIPT_10_MIN_REVIEWED_v3.md) ซึ่งระบุว่าค่าเวลาที่รายงานเป็นผลทดลองเดิม ไม่ใช่ความยาวคลิป

กรอบเวลารวมไม่เปลี่ยน: เข้าสไลด์ 18 ที่ 5:20 เปิดเรื่อง 15 วินาที + คลิป 2 นาที ออกจากเดโมที่ 7:35 และจบหน้า 21 ประมาณ 9:00 นาที
