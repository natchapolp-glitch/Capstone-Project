## ศัพท์ที่ควรพูดเป็นภาษาคนทั่วไป

- **YOLO:** โมเดลหาตำแหน่งเอกสารในภาพ ส่วนนี้ยังไม่ได้อ่านข้อความ
- **IoU:** พื้นที่กรอบที่ทับกันหารพื้นที่รวมของสองกรอบ ใช้เทียบกรอบทำนายกับกรอบอ้างอิง
- **mAP@0.5:** สรุป precision/recall ของการตรวจจับที่เกณฑ์ IoU 0.5 ไม่ใช่สัดส่วนตัวอักษรที่อ่านถูก
- **OCR:** แปลงภาพตัวหนังสือเป็นข้อความ EasyOCR/Tesseract เป็นเครื่องมือที่เปรียบเทียบ
- **micro CER:** รวมจำนวนแก้ตัวอักษรทั้งชุดแล้วหารจำนวนตัวอักษรอ้างอิงรวม ภาพที่ข้อความยาวมีน้ำหนักมากกว่า
- **Local LLM:** โมเดลภาษาที่ประมวลผลในเครื่อง ในการทดลองนี้รับข้อความจาก OCR หรือผู้บันทึก ไม่ได้รับภาพตรง ๆ
- **Qwen3 0.6B/1.7B:** ขนาดโมเดลประมาณ 0.6/1.7 พันล้านพารามิเตอร์
- **Quantization:** ลดความละเอียดตัวเลขของน้ำหนักโมเดลเพื่อลดทรัพยากร Q4_K_M ในงานนี้แปลงต่อจาก Q8_0 จึงมีข้อจำกัดในการแยกผลของการบีบอัด
- **Grammar / schema:** grammar จำกัดรูปแบบการสร้างข้อความ ส่วน schema กำหนดช่องและชนิดข้อมูล เช่นยอดรวมเป็นตัวเลข ทั้งคู่ไม่รับรองว่าค่าตรงใบเสร็จ
- **JSON:** รูปแบบข้อมูลเป็นช่องและค่าเพื่อให้โปรแกรมอ่านต่อได้
- **MQTT:** ส่งข้อความผ่าน broker ตามชื่อ topic ส่วน Home Assistant เป็นระบบที่รับและแสดงค่า
- **event_id:** รหัสเหตุการณ์ ต้องตรงกันทั้งต้นทางและปลายทางเพื่อกันสับสนกับค่าค้าง
- **RSS:** หน่วยความจำจริงที่กระบวนการใช้ ณ ช่วงวัด ค่า Windows กับบริการ Linux แยกกัน ไม่บวกแล้วเรียก RAM รวมโดยไม่มีขอบเขต
- **warm-up / warm:** รอบเตรียมโมเดลและการรันขณะที่โหลดโมเดลอยู่แล้ว ต่างจาก cold start ที่รวมการโหลด
- **RKNN / NPU:** RKNN เป็นชุดเครื่องมือสำหรับโมเดลบน Rockchip ส่วน NPU เป็นหน่วยประมวลผล AI ผล SDK บน PC ไม่แทนผลอุปกรณ์ RK3588 จริง

## คำถามที่อาจถูกถามหนัก

**OCR ผิดมากแล้วทำไปเพื่ออะไร?** ผลนำร่องทำให้เห็นคอขวดจริงก่อนย้ายฮาร์ดแวร์ ขั้นต่อไปต้องปรับภาพ/วิธีอ่านและทำเฉลยฟิลด์ การส่งถึง HA ยืนยันการเชื่อมระบบได้ แต่ยังไม่อ้างว่าเหมาะใช้งานอัตโนมัติโดยไม่ตรวจ

**ทำไมเดโมใช้ Tesseract ทั้งที่ EasyOCR CER ต่ำกว่า?** ตาราง CER และ configuration เดโมตอบคนละคำถาม เดโมใช้ Tesseract ตามรอบที่ตรึงเพื่อวัดการเชื่อมระบบ ไม่ได้พิสูจน์ว่าเป็น OCR ที่เหมาะที่สุด ต้องวัด trade-off ภายใต้เงื่อนไขเดียวกันเพิ่ม

**grammar ทำให้ดีขึ้นทุกกรณีหรือไม่?** ตารางนี้ดีขึ้นหรือคงเดิมในหลายเงื่อนไข แต่มีคำตอบจบไม่ครบ โดยรวมพบชนเพดาน tokens 6 รอบ และเปิด grammar 3 รอบในกลุ่มนั้น จึงยังต้องตรวจ status/parse/schema ทุกครั้ง

**ทำไม LLM ใช้เพียง 6 ภาพ?** เป็นชุดย่อยที่เลือกตามความยาวข้อความแล้วตรึงไว้ก่อนดูผล ไม่ใช่สุ่มเพื่อแทนประชากรทั้งหมด การรันซ้ำ 3 ครั้งเพิ่มรอบวัด ไม่เพิ่มจำนวนภาพอิสระ

**Robot ผ่านแปลว่าผลงานวิจัยแม่นหรือไม่?** Robot/Selenium ตรวจหน้าเว็บ การเรียกโมเดล การแก้ฟอร์ม การส่ง และการอ่านค่ากลับ ค่าที่กรอกโดย Robot เป็นข้อมูลสังเคราะห์ ไม่ใช่ผู้ตรวจหรือเฉลย JSON

**AVG กักไฟล์แล้วสรุปว่าปลอดภัยได้ไหม?** พบรายการกักกันและตรวจ archive ตรงกับรุ่นที่ผู้เผยแพร่ให้ไว้ การตรง hash ยืนยันที่มาของไฟล์ ไม่ใช่ผลวิเคราะห์ว่าการตรวจจับเป็น false positive

หากไม่มีหลักฐานตอบ ให้พูดว่า “ส่วนนี้ยังไม่ได้ทดลองครับ แผนวัดคือ…” แล้วระบุตัววัด/ข้อมูลที่ต้องใช้ หลีกเลี่ยงเดาตัวเลขหรือบอกว่าจะแม่นขึ้นแน่นอน

## คำถามเกี่ยวกับคลิปอ่านภาพจริง

**ในคลิปกดอ่านภาพใหม่จริงหรือเปิดผลเก่า?** แผนคลิปหลักกดอ่านภาพใหม่จริง เก็บภาพ กรอบ OCR/JSON การตรวจแก้ และ event ที่ HA รับจากรอบเดียวกัน ผลย้อนหลังใช้เฉพาะสำรองเมื่อคลิปเปิดไม่ได้ ต้องตอบหลังตรวจไฟล์คลิปจริงแล้ว

**ระบบทำเสร็จภายในสองนาทีหรือไม่?** สองนาทีคือความยาวคลิปตัดต่อ มีการตัดช่วงรอและย่อการตรวจตามที่กำกับ ไม่ใช่เวลา inference หรือเวลาทำงานจริงทั้งหมด ค่า 10.758 วินาทีในหน้า 19 เป็นผลทดลองเดิมที่มีขอบเขตต่างกัน

**ถ้าแก้ข้อมูลเองแล้ววัดอะไรได้?** คลิปสาธิตลำดับที่มีผู้ใช้ตรวจและการส่งถึง HA ผลโมเดลดิบยังเก็บแยกอยู่ การแก้ด้วยมือและส่งสำเร็จไม่ได้เป็นคะแนนความถูกต้องของโมเดล
