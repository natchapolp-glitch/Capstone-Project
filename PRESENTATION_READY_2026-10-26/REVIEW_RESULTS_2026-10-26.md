# ผล review ชุดพรี 10 นาที

> อัปเดตแผน: ผู้ใช้เลือกอัดคลิปกดอ่านภาพจริง ใช้ [บทอัดคลิป](RECORD_DEMO_SCRIPT.html), บทพูด v3 และ PPTX v3 ที่เปลี่ยน notes หน้า 18 ภาพสไลด์ 21 หน้าเหมือน v2 รายงานการทดสอบด้านล่างเป็นหลักฐานเดิม การแก้บทครั้งนี้ไม่ได้เพิ่มผล Robot หรือรับรองว่าคลิปอัดเสร็จแล้ว

## ข้อสรุป

สไลด์/บทพูดและคู่มือพร้อมใช้ซ้อม ระบบเดโมผ่าน Robot Framework + SeleniumLibrary บน Chrome ครบ 7/7 ในการรันครั้งเดียว `run-20261026-185448` ยังไม่มีคลิปจริงและยังไม่ได้จับเวลาการพูดของนักศึกษา จึงแยกสถานะตรวจทางเทคนิคออกจากความพร้อมขึ้นเวที

## สิ่งที่พบและแก้

| ระดับ | สิ่งที่พบ | การแก้/หลักฐาน |
|---|---|---|
| สูง | llama-server.exe หาย ทำให้รันภาพจริงไม่ได้ | พบ AVG chest/index.xml ระบุไฟล์และ IDP.Generic หลังผู้ใช้แจ้งปิด antivirus ได้คืนเฉพาะ exe จาก archive เดิม ซึ่ง hash ตรงกับ release ทางการ b11714 |
| สูง | เปิดบริการแล้วเคยขึ้น READY แม้ runtime ขาด | เพิ่ม preflight ตรวจ exe/ไฟล์โมเดลก่อนเริ่ม live mode เพิ่มโหมด SavedResultsOnly พร้อมข้อความแยก และเปลี่ยน StopIteration เป็น error ที่บอกจุดแก้ |
| สูง | ภาพจริง/กรอบโหลดไม่ครบด้วย ERR_CONNECTION_RESET | Selenium แยกยืนยันปัญหา หลังเปลี่ยน server เป็น HTTP/1.1 แบบคงการเชื่อมต่อ Chrome โหลดครบและ Robot ผ่าน รอบวินิจฉัย urllib ที่ส่ง Connection: close ยังพบ reset จึงไม่อ้างว่าทุก HTTP client หายหรือทราบต้นเหตุเครือข่ายทั้งหมด |
| กลาง | Test ที่พึ่งรอบก่อนล้มต่อกัน และ browser log มี 400 จากกรณีตั้งใจไม่ใส่ชื่อ | ให้ skip เมื่อ prerequisite ไม่สำเร็จ แยกเฉพาะ 400 ของการตรวจชื่อที่คาดไว้ และยังตรวจ severe errors อื่น ไม่ลดเงื่อนไข LLM/schema/ภาพ |
| กลาง | notes ใน PPTX ยังเป็นบทเดิม และหน้า 18 พูดถึงคลิปที่ยังไม่มี | ใส่บทหลัก 10 นาทีครบ 21 หน้า เก็บรายละเอียด/แหล่งเดิมเป็นส่วนเตรียมตอบคำถาม ปรับหน้า 18 ให้กล่าวถึงเดโมโดยไม่อ้างว่ามีคลิปแล้ว |
| กลาง | คู่มือเดิมยาวเกินเวลาพรีและไม่มี Q&A ครบหน้า | เพิ่ม runbook 120 วินาที แผนสำรองผลย้อนหลัง และ Q&A 21 หน้า รวมคำศัพท์/ขอบเขตตัวเลข |
| กลาง | เปิดผล Robot ย้อนหลังแล้วชื่อผู้ตรวจเติมชื่อเจ้าของงานแทนผู้ยืนยันเดิม | API/UI แสดงผู้ยืนยันจาก edit revision ล่าสุด และ Robot ตรวจว่าชื่อที่แสดงตรงบันทึกจริง |

การตรวจ hash ยืนยันว่า archive ตรงกับไฟล์เผยแพร่ ไม่ใช่การพิสูจน์ว่าการแจ้งเตือน antivirus เป็น false positive ไม่ได้เปลี่ยนการตั้งค่า antivirus หรือเพิ่ม exclusion โดยผู้ช่วย

## สไลด์และบทพูด

- ตรวจ PNG จาก PDF ที่ PowerPoint ส่งออกครบ 21 หน้า ไม่พบข้อความล้นหรือกล่องทับจนอ่านไม่ได้
- PDF v2 หน้า 1–17 และ 19–21 ตรงกับภาพเดิมทุกพิกเซล หน้า 18 ตรวจภาพใหม่แล้ว
- ไฟล์ PPTX ผ่าน package/layout/font checks มีตารางแก้ไขได้หน้า 17–19
- ตรวจ notes หลักตรงกับบทพูดทั้ง 21 หน้า และคงข้อมูลอ้างอิงเดิมใน notes ส่วนเพิ่มเติม
- ตรวจจำนวนภาพ 59/24/35, CER 82.36%/94.57%, ตัวหาร 28,011, ตาราง LLM ทั้ง 16 ช่อง รวม 288 รอบ และเวลามัธยฐาน 10.758 วินาทีตรงผลที่บันทึก
- footer วันที่ 18 ต.ค. อ้างชุดผลความก้าวหน้าเดิม การ review วันนี้ไม่ได้เพิ่มคะแนนวิจัยใหม่
- Builder Artifact Tool เขียน candidate และ render สำเร็จแต่ exit 1 เช่นเดียวกับรอบก่อน จึงไม่รายงาน builder ว่า exit 0 ตัว finalizer exit 0 และ PowerPoint เปิด/ส่งออก PDF ได้
- เปิด deck ผ่าน PowerPoint เพื่อส่งออก PDF ยังไม่ได้ทดสอบ Presenter View หรือการเล่นคลิปใน Slide Show

รอบผ่านใช้ภาพ `R74946CAAC57E`, receipt `f63be3b7-e6e5-4178-b79e-46b1b7cc0c3c`, pipeline `5c4ba623-b27a-44b7-b7ce-90ae63edb8a1`, event `f63be3b7-e6e5-4178-b79e-46b1b7cc0c3c:1` ค่า 45 และ 1 ตรงกันทั้งสอง sensor

## ยังต้องทำก่อนพรีจริง

พยายามเริ่ม Computer Use เพื่อตรวจ Slide Show แล้วสองครั้ง แต่ node_repl kernel เริ่มไม่สำเร็จด้วย `helper_sandbox_lock_failed / SetNamedSecurityInfoW ... 5` จึงไม่ใช้ผล export PDF แทนการรับรอง Presenter View/การเล่นคลิป

1. เจ้าของงานตรวจข้อมูลจากภาพเพื่อใช้คลิปตรวจจริง หรือเลือกผลย้อนหลังและบอกที่มาอย่างชัดเจน
2. อัด/ตรวจคลิปไม่เกิน 2 นาทีหากเลือกวิธีคลิป ปัจจุบันไม่มีไฟล์คลิปและไม่ได้ฝังใน PPTX
3. ซ้อมทั้งสองคนพร้อมคลิกจริงสองรอบ จบไม่เกิน 9:30 นาที แล้วลองถามข้ามช่วงสไลด์
4. ผลผ่านนี้เกิดหลังผู้ใช้แจ้งปิด antivirus ยังไม่ได้ทดสอบในสภาพเปิดกลับ ควรคืนการป้องกันเครื่องและตรวจ runtime/เดโมซ้ำในสภาพที่จะใช้พรี
