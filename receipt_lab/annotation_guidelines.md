# คู่มือลงเฉลยชุดนำร่องใบซื้อสินค้า 20 ภาพ

ไฟล์ภาพและเฉลยที่มีข้อความจากเอกสารจริงให้อยู่ใน `C:\Users\NATCHAPOL\SeminarLab` นอก OneDrive เท่านั้น รายชื่อภาพที่คัดแล้วอยู่ใน `reports\pilot_itemized_20.csv` ซึ่งเป็น **20 ภาพไม่ซ้ำระดับไฟล์** ยังไม่ใช่ 20 ตัวอย่างที่ทำเฉลยเสร็จหรือผลวัดความแม่นยำ

## หน่วยที่นับ

- หนึ่งแถวในชุดนำร่องคือหนึ่งภาพ ภาพ 9 ภาพมีใบซื้อสินค้าสองหน้าอยู่ในภาพเดียว ให้ถอดเป็นธุรกรรมเดียวและอ่านทั้งสองหน้าก่อนทำ JSON
- ยังไม่กำหนด train/test split จนกว่าจะตรวจเลขที่ใบเสร็จและวันที่ว่าธุรกรรมไม่ซ้ำกัน โดยเฉพาะเอกสารหลายหน้า
- ใบแจ้งหนี้ค่าหอ ใบรับชำระค่าบริการ และใบส่งของไม่อยู่ในชุดหลัก เก็บไว้เป็นกรณีขอบเขตของระบบ

## เฉลยข้อความ OCR

บันทึก `ground_truth_text\<doc_id>.txt` จากภาพต้นฉบับด้วยคน อ่านเรียงตามลำดับหน้าและบนลงล่าง รักษาตัวสะกดกับตัวเลขตามที่เห็นในภาพ หากส่วนใดอ่านไม่ได้ให้บันทึกตำแหน่งไว้ในบันทึกงาน อย่าเติมข้อความจากผล OCR เดาเอง และอย่าใส่ชื่อผู้ซื้อ ที่อยู่ เบอร์โทร เลขสมาชิก หรือข้อมูลส่วนตัวที่ไม่จำเป็นลงในเฉลยที่ใช้รายงาน หากมีข้อความส่วนตัวในภาพให้ทำสำเนาปกปิดก่อนนำเสนอ

## เฉลย JSON

บันทึก `ground_truth_json\<doc_id>.json` หลังตรวจจากภาพ ไม่คัดลอกผล OCR มาเป็นเฉลย โครงสร้างที่ scorer ปัจจุบันอ่านคือ:

```json
{
  "store_name": "ชื่อร้านตามใบเสร็จ",
  "date": "YYYY-MM-DD",
  "items": [
    {"name": "ชื่อสินค้าตามใบเสร็จ", "quantity": 1, "unit_price": 0.0, "category": null}
  ],
  "total": 0.0
}
```

- `date` ใช้วันที่ซื้อที่พิมพ์บนใบเสร็จ แปลง พ.ศ. เป็น ค.ศ. ด้วยการลบ 543 เฉพาะเมื่อต้นฉบับระบุว่าเป็น พ.ศ.; วันที่กำกวมให้เป็น `null` และบันทึกเหตุผลไว้
- `quantity` ใช้ตัวเลขจำนวนที่พิมพ์จริง อาจเป็นทศนิยมสำหรับสินค้าชั่งน้ำหนัก ไม่เดาเป็น 1 หากใบเสร็จไม่ระบุและกำกวม
- `unit_price` คือราคาต่อหน่วยที่พิมพ์จริง หากมีแต่ราคารวมและคำนวณย้อนกลับไม่ได้แน่ชัดให้เป็น `null`; ไม่แปลงราคาโปรโมชันโดยเดา
- `total` คือยอดจ่ายสุทธิของธุรกรรมหลังส่วนลดตามที่พิมพ์ ถ้ามีหลายยอดให้ตรวจว่าเป็นยอดสุดท้าย ไม่รวมเงินทอน
- `items` นับสินค้า/บริการที่ซื้อแต่ละบรรทัด ไม่สร้างรายการจาก VAT ยอดรวม เงินทอน หรือบรรทัดส่วนลด หากใบเสร็จแสดงส่วนลดของรายการ ให้จดวิธีตีความในบันทึกก่อนให้คะแนน
- `category` ยังไม่มีเกณฑ์จัดประเภทที่ตกลงร่วมกัน ให้ใช้ `null` ทุกแถวในรอบแรก และอย่าอ้างคะแนนหมวดสินค้า
- จำนวนเงินเป็นเลขบาทแบบ JSON number; ชื่อร้าน/สินค้าใช้รูปเขียนเดียวกันทั้งเฉลยและผลโมเดลหากต้องการใช้ exact match

หลังทำเฉลย ให้คนอีกคนตรวจอย่างน้อยวันที่ ยอดรวม จำนวน และรายการสินค้าในภาพที่ใช้รายงาน แล้วเปลี่ยนสถานะ `ground_truth_status` ใน CSV เป็น `double_checked` เฉพาะที่ตรวจแล้ว ขณะนี้ทุกแถวยังเป็น `not_annotated`

## ข้อจำกัดของการวัด

ชุดนี้มี Makro 15, Thai Watsadu 4, Advice 1 จึงเป็น pilot ที่เอนเอียงไปทางร้านเดียว ใช้ดูความเป็นไปได้และปัญหาจริง ไม่สรุปความแม่นยำทั่วไปหรือประสิทธิภาพบน NPU จากชุดนี้ คะแนน CER ต้องเทียบกับข้อความที่คนตรวจ; จำนวนกรอบข้อความหรือค่า confidence ของ EasyOCR ไม่ใช่ accuracy

`json_extraction_scorer.py` จับคู่ชื่อสินค้าด้วย fuzzy matching และรายงานจำนวนรายการที่เกินแยกจาก precision; ก่อนใส่ค่าลง Ass5/Ass6 ให้ตรวจสูตรและนิยาม metric อีกครั้ง
