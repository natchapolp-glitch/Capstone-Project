## หน่วยที่นับ

- หนึ่งแถวคือหนึ่งภาพ ภาพที่มีหลายใบ/หลายหน้าต้องตรวจว่าเป็นธุรกรรมเดียวกันหรือไม่ก่อนรวม JSON ไม่สรุปว่าเป็นธุรกรรมเดียวจากการอยู่ในภาพเดียวกัน
- ยังไม่กำหนด train/test split จนกว่าจะตรวจเลขที่ใบเสร็จและวันที่ว่าธุรกรรมไม่ซ้ำกัน โดยเฉพาะเอกสารหลายหน้า
- ใบแจ้งหนี้ค่าหอ ใบรับชำระค่าบริการ และใบส่งของไม่อยู่ในชุดหลัก เก็บไว้เป็นกรณีขอบเขตของระบบ

## เฉลยข้อความ OCR

กรอกข้อความทุกบรรทัดในขอบเขตภาพสำหรับตรวจ เรียงจากบนลงล่าง รักษาตัวสะกดกับตัวเลขตามภาพ หากอ่านไม่ได้ให้ระบุตำแหน่ง ไม่เดาจาก OCR หรือใช้ null แทนความอ่านไม่ออก รอบแรกใช้ OCR เป็นร่างได้ถ้าตรวจแก้กับภาพจริงและบันทึกว่าใช้ร่างช่วย รอบสองต้องเริ่มจากช่องว่าง เก็บข้อมูลส่วนตัวไว้ในพื้นที่ทดลองเท่านั้น ไม่แสดงในรายงาน หากปกปิดภาพหรือไม่วัดบางส่วน ต้องใช้ขอบเขตเดียวกันทั้งสอง OCR และเฉลย

## เฉลย JSON

ใช้ schema กลาง `receipt_schema.json` และบันทึกผ่านหน้าตรวจ/หน้าตกลงเฉลยใน `preboard\annotations` โครงสร้างที่ scorer ปัจจุบันอ่านคือ:

```json
{
  "merchant": "ชื่อร้านตามใบเสร็จ",
  "transaction_date": "YYYY-MM-DD",
  "items": [
    {"name": "ชื่อสินค้าตามใบเสร็จ", "quantity": 1, "unit": null, "unit_price": 20.0, "line_total": 20.0}
  ],
  "grand_total": 20.0,
  "currency": null
}
```

- `transaction_date` ใช้วันที่ซื้อ แปลง พ.ศ. เป็น ค.ศ. ด้วยการลบ 543 เฉพาะเมื่อมีหลักฐานปฏิทินชัด วันที่มีแต่ปีสองหลักและยังตกลงวิธีตีความไม่ได้ให้ทำเครื่องหมายกำกวม ภาพนั้นยังไม่ผ่านเฉลยเต็ม ไม่ใช้ null กลบข้อมูลที่มีแต่ตีความไม่ได้
- `quantity` ใช้ตัวเลขจำนวนที่พิมพ์จริง อาจเป็นทศนิยมสำหรับสินค้าชั่งน้ำหนัก ไม่เดาเป็น 1 หากใบเสร็จไม่ระบุและกำกวม
- `unit_price`, `line_total` และ `unit` เก็บค่าที่ปรากฏตามภาพ ไม่คำนวณหรือเดาแทนข้อมูลที่ไม่พิมพ์ ค่าที่อนุมานถ้าจำเป็นต้องเก็บใน metadata แยก ไม่ปนเฉลยหลัก
- `grand_total` คือยอดจ่ายสุทธิหลังส่วนลดที่พิมพ์จริง ถ้ามีหลายยอดให้ตรวจยอดสุดท้าย ไม่รวมเงินทอน
- `items` นับสินค้า/บริการที่ซื้อแต่ละบรรทัด ไม่สร้างรายการจาก VAT ยอดรวม เงินทอน หรือบรรทัดส่วนลด หากใบเสร็จแสดงส่วนลดของรายการ ให้จดวิธีตีความในบันทึกก่อนให้คะแนน
- `currency` เก็บเมื่อมีหลักฐานตามกติกา ไม่เดาจากประเทศเพียงอย่างเดียว ไม่มี `category` ใน schema ปัจจุบัน
- จำนวนเงินเป็น JSON number; ชื่อร้าน/สินค้าคงตามภาพ ห้ามแก้คำตอบโมเดลให้ตรงเฉลยก่อนคิดคะแนน

เก็บการตรวจสองรอบแยกกันพร้อมชื่อ เวลา และ hash ของภาพ แล้วเทียบ/แก้ส่วนต่างในหน้าตกลงเฉลย เปลี่ยนสถานะเป็น `adjudicated` เมื่อมีหลักฐานครบเท่านั้น และบันทึก `single_reviewer_double_entry` ตามที่ผู้ใช้ยืนยัน ผู้วิจัยคนเดียวสองรอบไม่เท่ากับผู้ตรวจอิสระสองคน

## ข้อจำกัดของการวัด

ตรวจจำนวนร้านและจำนวนธุรกรรมจาก manifest รุ่นที่ใช้จริง แยกชุด development/evaluation/challenge ตามธุรกรรม ภาพที่อ่านครบอาจเอนเอียงตามความอ่านได้ จึงไม่สรุปความแม่นยำทั่วไปหรือผลบน NPU จาก pilot นี้ คะแนน CER ต้องเทียบกับข้อความที่คนตรวจ ความมั่นใจของ OCR ไม่ใช่ accuracy

กติกาคะแนนล่าสุดอยู่ใน `JSON_SCORING_PROTOCOL.md` รายการเกินลด precision แล้ว จำนวนรายการจับคู่ไม่สำเร็จไม่เท่ากับการพิสูจน์ hallucination ผลใหม่ต้องผ่าน review ก่อนนำไปเติม Ass5/Ass6 READY
