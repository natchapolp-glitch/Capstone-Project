# คู่มือคลิกและบทพูดเดโมสำหรับ Ass5

ใช้กับสไลด์ 16–19 ของชุด REVIEWED_2026-10-18 บทพูดหลักยังครอบคลุมครบ 21 สไลด์ เอกสารนี้ขยายช่วงเดโมตามหน้าเว็บที่ใช้ได้บน PC เครื่องนี้

## 1. เตรียมก่อนขึ้นพรี 10 นาที

1. เสียบไฟ ตั้งให้เครื่องตื่นระหว่างพรี และเปิดไฟล์ PowerPoint ชุด REVIEWED
2. ดับเบิลคลิก `OPEN_DEMO.cmd` ในโฟลเดอร์นี้ รอข้อความ READY ตัวเปิดจะตรวจบริการและคำขอหลักของหน้า Home Assistant
3. เปิดแท็บ A: http://127.0.0.1:8090/demo กด Ctrl+F5 หากเปิดค้างมาจากก่อนแก้หน้าเว็บ
4. เปิดแท็บ B: http://127.0.0.1:8123/config/tools/state เข้าบัญชีเดโมที่ให้ไว้ในบทสนทนาให้เรียบร้อยก่อนแชร์หน้าจอ
5. ในแท็บ B ใช้ช่องกรองรายการ entity ค้นหา `sensor.seminar_latest_purchase_total` แล้วดู state และ attributes ของรายการนั้น การสาธิตนี้ใช้การอ่านค่าที่รับจริง
6. เปิดแท็บ C สำหรับผลสำรอง: http://127.0.0.1:8090/demo?receipt=903a5782-771d-47ab-a2a1-882ebfaa735e
7. ซ้อมสลับ PowerPoint กับเบราว์เซอร์ด้วย Alt+Tab ปรับซูมให้ผู้ฟังอ่านได้ทั้งภาพและฟอร์ม ไม่จำเป็นต้องย่อหน้าเว็บทั้งหน้าให้อยู่ในจอเดียว
8. ลองช่วงเดโมด้านล่างหนึ่งรอบก่อนพรี การซ้อมยืนยันจะอัปเดตค่าล่าสุดใน Home Assistant ตามรายการที่ส่ง

หน้า Home location, Help us help you และการค้นหาอุปกรณ์ เป็นการตั้งค่าเครื่องที่ทำเสร็จแล้ว เริ่มสาธิตจากแท็บ A ได้เลย

## 2. สไลด์ 16: อธิบายกรอบตรวจจับ 30–45 วินาที

**ทำ:** อยู่บน PowerPoint ชี้ภาพต้นฉบับและภาพผลตรวจจับที่อยู่ในสไลด์

**พูด:** “ขั้นแรกโมเดล YOLO หาตำแหน่งเอกสารในภาพ ตัวอย่างบนสไลด์เป็นภาพที่เลือกจากชุดตรวจฉากเดิม เห็นกรอบหนึ่งกรอบที่ confidence 0.981 การทดลองนี้ยังอยู่บน PC ส่วนเดโมครบกระบวนการจะอยู่ในสไลด์ 18 ครับ”

ค่า confidence 0.981 และเกณฑ์แสดงผล 0.80 เป็นของภาพตัวอย่างบนสไลด์ 16 หน้าเดโมสดใช้การตั้งค่าตรวจจับของ pipeline อีกชุดหนึ่ง (`conf=0.25`) จึงไม่ยกสองค่านี้ไปบรรยายภาพสดทุกภาพ

## 3. สไลด์ 17: เชื่อมเข้าสู่ JSON

**ทำ:** อธิบายตารางรูปแบบ JSON ตามบทพูดหลัก

**พูดเชื่อม:** “การผ่าน schema บอกว่ารูปแบบใช้ต่อได้ แต่ชื่อสินค้าและยอดเงินยังผิดได้ ต่อไปผมจะเปิดต้นแบบให้เห็นทั้งผลโมเดลและจุดตรวจแก้ก่อนส่งครับ”

## 4. สไลด์ 18: เดโมสดประมาณ 3–4 นาที

เวลาเป็นงบสำหรับซ้อม ไม่ใช่ผลวัดประสิทธิภาพ ถ้าตรวจแก้ใช้เวลามาก ให้ขยายช่วงเดโมหรือใช้ผลบันทึกอย่างชัดเจน

### 4.1 เริ่มที่ภาพจริง

**คลิก:** Alt+Tab ไปแท็บ A เลือกภาพ `R74946CAAC57E` ร้าน 7-Eleven ตรวจว่าช่องหมุนภาพเป็น **หมุนทวนเข็ม 90°** แล้วกด **อ่านภาพด้วยระบบ** หนึ่งครั้ง

**พูด:** “ภาพนี้เป็นใบซื้อสินค้าจริง ระบบให้ผู้ใช้กำหนดทิศภาพก่อน แล้วตรวจกรอบ อ่านข้อความด้วย Tesseract และให้ Qwen3 0.6B Q4_K_M สร้าง JSON ภายในเครื่องโดยเปิดการบังคับรูปแบบครับ”

**ระหว่างรอ:** “รอบสดนี้มีเวลาเริ่มโมเดลรวมอยู่ด้วย ในการตรวจความพร้อมสามภาพใช้เวลาประมาณ 11–34 วินาที ตัวเลขนี้มีขอบเขตต่างจากชุดวัดที่โหลดโมเดลค้างในหน่วยความจำครับ”

### 4.2 แสดงผลแต่ละขั้น

**คลิก:** เมื่อมีผล ให้ชี้กรอบสีเขียว เลื่อนลงในแผงขวา แล้วเปิดหัวข้อ **ผลจากเครื่องมือก่อนผู้ใช้แก้ไข**

**พูด:** “กรอบสีเขียวคือผลตรวจจับของรอบนี้ ด้านนี้เป็นข้อความ OCR ที่ส่งต่อให้โมเดลภาษา และด้านล่างเป็น JSON ที่โมเดลสร้างก่อนแก้ไข เรายังพบการอ่านผิดและเอาข้อความอื่นมาปนเป็นสินค้า จึงต้องมีขั้นให้ผู้ใช้ตรวจครับ”

**ชี้:** ข้อความ OCR และ JSON ดิบ เก็บสองส่วนนี้ไว้ให้ผู้ฟังเห็นที่มาของข้อผิดพลาด แม้แก้ค่าในแบบฟอร์มแล้วผลดิบของรอบเดิมจะยังอยู่

### 4.3 ตรวจและแก้ก่อนส่ง

**คลิก:** กลับขึ้นมาที่ฟอร์ม **รายการสินค้า** เปรียบเทียบกับภาพ เปิดภาพต้นฉบับขนาดเต็มได้หากตัวอักษรเล็ก

| ช่อง | วิธีกรอกระหว่างเดโม |
|---|---|
| ร้าน | ตรวจชื่อร้านจากหัวใบเสร็จ |
| วันที่ | แปลงวันที่เป็น ค.ศ. รูปแบบ YYYY-MM-DD จากวันที่ในภาพ |
| ยอดรวม | ใช้ยอดสุทธิของการซื้อ ตรวจแยกจากเงินสดและเงินทอน |
| สกุลเงิน | ตรวจตามใบเสร็จ |
| แถวสินค้า | ลบแถวที่เป็นหัวใบเสร็จ รหัสเครื่อง หรือข้อความอื่น แล้วเพิ่ม/แก้เฉพาะรายการสินค้าจริง |
| จำนวน / หน่วย / ราคา / รวม | ตรวจแต่ละช่องกับภาพ ข้อมูลที่ไม่ปรากฏเว้นว่างได้ หากมีแต่อ่านไม่ออกต้องระบุข้อจำกัดในการนำเสนอ |
| ชื่อผู้ตรวจ | ใส่ชื่อผู้ที่ตรวจข้อมูลรอบนี้จริง |

**ตัวช่วยซ้อมเฉพาะภาพ R74946CAAC57E:** ภาพที่ตรวจดูแสดงยอดสุทธิ 45.00 บาท หนึ่งรายการ และวันที่ 17/10/69 ซึ่งแปลงเป็น 2026-10-17 ให้ตรวจภาพที่เปิดอีกครั้งก่อนกรอก โดยอ่านข้อความชื่อสินค้าเองจากบรรทัดสินค้า อย่าใช้ยอด 0 และรายการ 6 แถวจากผลโมเดลเดิมเป็นเฉลย ตัวช่วยนี้ไม่ใช่ชุดเฉลย JSON ที่นำไปคำนวณคะแนนวิจัย

**พูด:** “ตรงนี้ผมตรวจแก้เทียบกับใบเสร็จก่อนส่ง ข้อมูลในแบบฟอร์มหลังตรวจคือข้อมูลที่จะส่ง ส่วนผลดิบยังเก็บไว้ตรวจย้อนกลับ การมีตัวเลขใน JSON จึงยังไม่เพียงพอจะสรุปว่าโมเดลอ่านถูกครับ”

### 4.4 ยืนยันและอ่านค่ากลับ

**คลิก:** กด **ยืนยันและส่งข้อมูล** รอผล แล้วกด **ตรวจสถานะปลายทาง** ในส่วน Home Assistant

**ตรวจ:** ข้อความควรขึ้น **ได้รับรายการที่เลือกแล้ว** พร้อม event ID ตรงกับรายการที่ส่ง และมีเซนเซอร์สองตัวสำหรับยอดรวมกับจำนวนรายการ

**พูด:** “หลังยืนยัน ระบบเก็บข้อมูลและส่ง JSON ไปยัง MQTT broker บน PC เครื่องนี้ ที่ topic seminar/preboard/purchases/latest จากนั้น Home Assistant รับข้อความและแสดงยอดรวมกับจำนวนรายการ ด้านนี้อ่านค่ากลับจากปลายทางจริงครับ”

MQTT topic เป็นชื่อช่องข้อความ ไม่ใช่โฟลเดอร์ ไฟล์ หรือ URL สำหรับเปิดในเบราว์เซอร์

### 4.5 เปิด Home Assistant ให้เห็นข้อมูลที่รับจริง

**คลิก:** สลับไปแท็บ B ที่ http://127.0.0.1:8123/config/tools/state

1. กรอง entity `sensor.seminar_latest_purchase_total`
2. ดูค่า **State** เทียบยอดรวมที่เพิ่งยืนยัน
3. ดู **Attributes** หา `event_id`, `doc_id` และ `extraction` ภายใน extraction มีข้อมูลที่ส่ง เช่น merchant, transaction_date, grand_total และ items
4. เทียบ event_id กับแท็บ A เพื่อยืนยันว่าเป็นรอบเดียวกัน ไม่ใช่ค่าค้างจากรายการก่อน
5. เปลี่ยนตัวกรองเป็น `sensor.seminar_latest_item_count` เพื่อดูจำนวนรายการ และเทียบ event_id เดียวกัน

**พูด:** “หน้า Home Assistant แสดงข้อมูลจากเหตุการณ์เดียวกับที่ผมเพิ่งส่ง ยอดรวมและจำนวนรายการตรงกับ JSON หลังตรวจแก้ แสดงว่าระบบเชื่อมต่อกันได้ ส่วนความถูกต้องที่โมเดลอ่านเองต้องประเมินแยกจากขั้นส่งข้อมูลครับ”

### 4.6 กลับสไลด์

**คลิก:** Alt+Tab กลับ PowerPoint แล้วไปสไลด์ 19

**พูดปิดเดโม:** “เดโมนี้ได้ข้อมูลซื้อเข้าที่ตรวจสอบย้อนหลังได้ การคำนวณของคงเหลือหรืออัตราการใช้ยังต้องมีข้อมูลเพิ่ม ต่อไปเป็นผลวัดเวลาและหน่วยความจำจากชุดทดลองที่กำหนดไว้ครับ”

## 5. สไลด์ 19: อธิบายเวลาให้ตรงขอบเขต

**พูด:** “ตารางนี้มาจากสามภาพ ภาพละสามรอบ โหลดโมเดลค้างในหน่วยความจำและใช้การยืนยันอัตโนมัติ มัธยฐานจากภาพถึงสังเกตค่าใน Home Assistant คือ 10.758 วินาที ยังไม่รวมเวลาที่คนอ่านและแก้รายการ ส่วนการคลิกสดเมื่อครู่รวมการเริ่มโมเดลและเวลาที่ผมตรวจด้วย จึงไม่ควรนำเวลาทั้งสองแบบมาเทียบตรง ๆ ครับ”

คงตารางผลทดลองเดิมในสไลด์ 18–19 ไว้ได้ ถ้าค่าปัจจุบันใน HA เปลี่ยนหลังตรวจแก้ ให้บอกว่าตารางเป็นผลโมเดลในรอบทดลองที่บันทึกไว้ ส่วนค่าปัจจุบันเป็นข้อมูลของรอบสาธิตหลังตรวจแก้

## 7. คำถามที่อาจเจอ

- **ส่ง JSON ไปไหน:** MQTT broker ใน PC ที่ 127.0.0.1:18884 แล้ว Home Assistant ในเครื่องเดียวกันรับที่ topic seminar/preboard/purchases/latest
- **ทำไมยอดหรือชื่อสินค้าผิด:** OCR และการจัดข้อมูลของโมเดลภาษายังผิดได้ จึงมีขั้นตรวจแก้ และยังไม่มีคะแนนความถูกต้องระดับฟิลด์จากเฉลยครบ
- **เป็นผลบนบอร์ดหรือยัง:** เป็น PC pilot ผล NPU และพลังงานบน RK3588 ยังรอบอร์ด
- **59 ภาพคือเดโมครบ 59 หรือไม่:** 59 คือชุดภาพและข้อความอ้างอิงหนึ่งรอบ ส่วนตรวจความพร้อมเดโมวันที่ 21 ตุลาคมรันใหม่ 3 ภาพ ชุดวัดเวลาเดิมคือ 3 ภาพ ภาพละ 3 รอบ
- **0.981 คือความแม่นยำทั้งระบบหรือไม่:** เป็น confidence ของกรอบในตัวอย่างสไลด์ 16 ไม่ใช่คะแนน OCR หรือความถูกต้อง JSON
- **ตรวจแก้แล้วถือว่ามีเฉลยครบหรือยัง:** การตรวจหนึ่งภาพเพื่อสาธิตไม่ได้ทำให้ชุดเฉลย JSON ทั้งชุดสมบูรณ์
